# GPS・通行確認・ルート評価の設計

## 1. GPSの利用範囲【確定】

Web Geolocation APIを利用する。主用途は現在地表示、実走軌跡の保存、投稿済みおすすめ道との通行照合、経路表示中の現在地追従。

- GPS記録は明示的な開始・終了で制御する。
- Webページが**フォアグラウンド表示中**であることを前提とする。
- HTTPSとブラウザの位置情報許可が必要（localhost上の開発環境は例外）。
- 地図の閲覧と本人の軌跡サーバー保存は分離する。
- 記録した全経路を自動公開しない。本人の選択した区間だけ投稿する。

## 2. 保存候補と補正【**暫定設計値**】

GPS点の候補項目：緯度、経度、accuracy(m)、取得時刻。速度、進行方向、高度は取得できる場合の補助値。

初期の保存間隔案：前回採用点から**5m以上移動**、または**10秒以上経過**。ビル街では誤差で距離が増えるため、無条件の距離加算は避ける。

補正案：
1. accuracyが著しく悪い点を無視する。50m超を警戒、100m超を除外候補とする。
2. 同位置・短時間の重複点を間引く。
3. 隣接点の距離/経過時間から徒歩として不自然な高速移動やジャンプを検出する。
4. 必要に応じて移動平均などで表示用軌跡を平滑化する。
5. 生データ・補正後の差を、実走実験で比較する。

これらは**合意済みの固定閾値ではない**。実機GPS、道路環境、画面描画品質に応じて決定する。

## 3. 実走区間の投稿【確定】

- 投稿区間は自分の記録セッションから選択する。
- もとの生GPS履歴全体は本人限定で保持する。
- 投稿は公開用の線形データを別に生成・保持する。
- すべての投稿が実際に歩行可能な公道であると自動保証してはいけない。私有地や立入禁止の懸念を考慮する。
- 始点・終点が個人宅などの位置を示すことがあるため、投稿時のプレビューや匿名化/切り詰めを設計する。

## 4. 通行確認【方式は確定、数値は**暫定**】

他のユーザーのGPS記録が投稿区間と一定以上重なった場合、「通行確認」候補として集計する。

| 条件 | 暫定案 |
| --- | --- |
| ユーザー | 投稿者本人による確認数加算はしない |
| 重複 | 投稿区間の**70%以上**を一定の許容距離内で実走 |
| 水増し防止 | 同一ユーザーによる同一投稿の確認は1回として扱う |
| 確認済みへの昇格 | **別ユーザー3人以上**による有効な通行確認 |

空間距離の許容値、方向一致、連続性、測位精度、時間帯、端末偽装にどう対処するかは未決定。単純に「近いGPS点が数個ある」だけで全区間を確認済みにしない。

## 5. ルート生成・比較【確定した考え方】

徒歩経路の形状は既存のルート探索サービスから候補を取得する。独自アプリ側では、距離や学生の投稿・通行確認情報を候補の線と重ね合わせて評価する。

比較対象：
- **最短ルート:** 距離・想定時間を優先する基準候補。
- **おすすめ通学ルート:** 学生投稿や通行確認を反映した評価が高い候補。

ルート探索サービスが複数候補を返さない場合、**スコアを変えるだけでは道の形が変わらない**。異なる候補が存在しない場合は正しく明示する。投稿区間を経由させる経由点方式などは技術検証後の設計判断とする。

## 6. 通学快適スコア【配点は**暫定案**】

| 評価項目 | 初期配点例 | 解釈 |
| --- | ---: | --- |
| 移動効率 | 35 | 距離・所要時間、遠回りペナルティ |
| おすすめ道の利用率 | 25 | 候補経路が公開おすすめ区間と重なる割合 |
| コミュニティ確認 | 15 | 別ユーザーの通行確認実績 |
| 利用者評価 | 15 | 参考になった等の投稿評価を正規化 |
| 道路特徴 | 10 | タグ・道路属性を条件付きで加点 |

候補間で0〜1に正規化して100点満点の指標とする案。距離・所要時間の大幅な増加を抑制する。タグは主観情報なので、未測定の歩行者数・治安・信号数を客観指標として偽らない。

結果画面では、「最短より+◯分」「おすすめ道の重複率」「確認済み区間数」など、**実際に計算できた根拠**を表示する。

## 7. 検証計画

- 学校・駅周辺の決めた複数コースを歩き、元GPSと補正GPSの軌跡差、測定距離、単発ジャンプを比べる。
- 同じ区間を別ユーザーが歩き、通行確認が重複なく計上されることを確かめる。
- 複数の発着地点で、最短／おすすめの距離・時間・推薦区間重複率を比べる。
- 学生の主観評価を別途収集して、スコアの重みを見直す。
- 実測値や検証結果がないものは、成果として断定しない。

## 8. 設計確定が必要な事項

学校入口座標／半径2kmの厳密な適用／GPS閾値／空間マッチング許容値／ルート探索サービス選定／代替経路生成方法／公開データ匿名化／確認済み基準と水増し対策。
