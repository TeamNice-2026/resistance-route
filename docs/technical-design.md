## 2. システム構成

- **ブラウザ:** 画面、地図、Geolocation API、ユーザー操作、現在地追従。
- **バックエンドAPI:** 認証・権限、GPS記録データの取扱い、投稿・評価・通行確認、ルート取得・独自スコア、外部APIキーの管理。
- **PostGIS:** ユーザーの非公開GPS点/線、公開おすすめ線、投稿タグ、評価、位置関係の空間検索。**DBのホストは未選定。** 学校外のDBも候補として比較する。
- **外部地図タイルサービス:** MapLibreで表示する地図データを提供。利用規約、帰属表示、料金を確認して選ぶ。
- **既存徒歩ルート探索API:** OSMなどの道路ネットワークを使って経路候補を生成。対応地域、候補の複数取得、料金と制限を検証する。

本アプリは**独自の道路グラフを一から作らない**。候補生成と独自スコア算出を分離する。

## 3. データモデル【**設計候補。スキーマ未確定**】

| エンティティ候補 | 主な属性案 | 備考 |
| --- | --- | --- |
| users | id, email, display_name, 認証情報, created_at | 認証方式未決定。個人情報は非公開 |
| gps_sessions | id, user_id, 開始・終了日時, 距離, 状態 | 記録1回につき1件 |
| gps_points | id, session_id, geom(Point), accuracy_m, recorded_at | **本人限定の生GPS記録** |
| route_posts | id, user_id, source_session_id, geom(LineString), comment, status | 選択した**公開区間のみ** |
| tags | id, name/code | 近道、静か等 |
| route_post_tags | post_id, tag_id | 多対多 |
| helpful_votes | post_id, user_id | 投稿への有用性評価（重複不可） |
| route_verifications | post_id, user_id, session_id, overlap_ratio | 別ユーザーの実走照合 |
| reports | id, post_id, reason, status | 発展的な通報対応候補 |

PostGISの空間インデックス（GiSTなど）を活用する方針。実際の型、主キー、外部キー、削除時の連鎖、マイグレーションを**実装前に確定**する。

地理データの座標系、GeoJSONの緯度・経度順、UTCなどの時刻形式もAPI/DB設計Issueで合意する。

具体的なHTTPメソッド・URL・エラー形式・ページング・認証方式は**未決定**。API仕様を確定したらOpenAPIとdocsを更新する。

## 5. 認証・セキュリティ【方針】

- ログイン機能を提供する。ゲスト利用と登録ユーザー限定操作を分ける。
- パスワードを自前管理する場合は平文保存禁止。Argon2idなど安全なパスワードハッシュを利用する。
- Cookieセッションまたは管理型認証など、**実装方式を比較してから決定**する。
- HTTPS、権限チェック、CSRF/XSS対策、入力検証、認証APIのレート制限を検討する。
- 本人のGPS軌跡は本人だけが閲覧・削除できる。公開投稿は区間を限定する。
- デバッグログ、テスト、Issue・PRへ実GPS履歴や個人情報を転載しない。
- 外部地図・ルートサービスは規約、API上限、請求額、出典表示条件を確認する。
