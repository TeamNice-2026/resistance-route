# 画面仕様・利用者フロー

この文書は必要な画面と機能の位置づけを定めるもの。Figmaなどの詳細UI、色、コンポーネント配置は今後の設計で決める。

## 1. モバイル優先の基本原則【確定】

- ホームは**地図中心**。最優先操作を「学校へ行く」にする。
- 「任意目的地検索」も同じ画面から操作できる。
- 地図上に現在地、ルート、公開おすすめ区間を表示。
- GPS記録中は目立つ「記録中」状態を表示。
- 最短とおすすめは、数値と理由で比較できるようにする。
- 位置情報拒否、圏外、記録精度不足、ルートなしの場合は短い日本語で案内する。
- スマホで操作可能なボタンサイズと地図の視認性を優先する。

## 2. 必要な画面・状態

| 画面 | 表示内容 | 主な操作 |
| --- | --- | --- |
| ホーム / 地図 | 現在地・学校・公開おすすめ道・対象範囲 | 学校へ行く、目的地検索、GPS記録 |
| ルート比較 | 最短候補、おすすめ候補、距離、時間、説明 | 候補選択、案内開始 |
| ナビ表示 | 経路線・GPS現在地・進行状態 | 現在地追従、再検索、終了 |
| ユーザー登録・ログイン | 登録フォーム、ログインフォーム | 認証、ログアウト |
| GPS記録中 | 時間・距離・測位精度・軌跡 | 開始・終了（再開/一時停止は未決定） |
| GPS履歴 | 本人の記録一覧と地図上の線 | 詳細、区間選択、削除 |
| 投稿作成 | 選択区間プレビュー、タグ、説明 | 内容確認、投稿 |
| おすすめ道詳細 | 公開区間、タグ、説明、評価・確認状況 | 参考になった、一覧へ戻る |
| マイページ | 自分の履歴と投稿、アカウント設定 | 削除、ログアウト、プロフィール |

## 3. 通学ナビ

ホーム → 学校へ行く → 目的地・現在地の確認 → 候補比較 → ルート選択 → 地図上で現在地追従 → 終了。

任意目的地はホームの検索操作から同じ比較画面へ遷移する。

## 4. 実走記録とおすすめ道

ログイン → 記録開始 → 徒歩実走 → 記録終了 → 自分の履歴 → 投稿する区間を選択 → タグ・任意コメント → プレビュー → 新規ルートとして公開。

公開された線以外のGPS履歴を他人が見られないようにする。

## 5. 投稿の閲覧・確認

地図上で公開区間をタップ → 投稿詳細 → タグ・説明・新規/確認済み表示 → ログイン済みユーザーが「参考になった」を押す。

通行確認は投稿詳細画面のボタンを押しただけでは成立しない。**別ユーザーの有効なGPS実走記録との照合**が必要。

## 6. 明確に表示すべき制限

- 現在地を利用するには位置情報許可が必要。
- フォアグラウンドを離れた際のGPS記録継続は保証しない。
- タグは投稿者の感じた情報で、混雑や安全性を保証しない。
- 「コミュニティ確認済み」は安全確認済みを意味しない。
- 「最短」「おすすめ」に同一の候補が選ばれた場合はその理由を示す。

## 7. 詳細設計が未完了の項目

地図上のUI配置、認証フォーム項目、目的地検索方式（施設名検索・地図タップ等）、ルート外逸脱時の挙動、記録の一時停止、履歴公開区間選択UI、アクセシビリティ細部。
