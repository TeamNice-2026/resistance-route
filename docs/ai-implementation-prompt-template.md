## 最初に確認する

- `AGENTS.md`、`docs/development-workflow.md`、`docs/architecture.md`
- Claude Codeなら `CLAUDE.md`
- GitHub Issue **#[番号]** の本文・関連コメント
- 変更対象の既存コードとテスト

## 作業するIssue

- Issue: #[番号]
- 目的: [解決したい課題・ユーザー価値]
- ブランチ: `[feature/issue-番号-概要]` （最新の`main`から作成）

## 変更対象・非対象

- 実装すること: [対象画面 / API / DB / ファイル]
- 実装しないこと: [他Issueの機能、勝手な仕様変更、無関係なリファクタリング]
- API・DBに影響する場合は実装前に変更案を提示して確認する。

## 受入条件（Issueに一致させる）

- [ ] [正常系]
- [ ] [異常系・権限系]
- [ ] [必要なテスト・実機確認]

## 手順

1. 関連コードを調査し、実装方針と変更範囲を短く説明する。
2. Issueと現状に矛盾があれば確認を求め、独断で仕様変更しない。
3. 実装と自動テストを行い、必要な手動テストを実施する。
4. テスト・型チェック・ビルドを実行し、結果を記録する。
5. 差分を確認し、秘密情報・不要ファイル・実GPSログの混入を確認する。
6. **作業ブランチへコミット・Pushし、PRを作成する。**
7. PRに関連Issue（`Closes #番号`）、変更点、テスト結果、既知の制限を記載する。
8. **`main`へ直接pushしない。マージを実行しない。** 管理者とChatGPTの最終確認に引き渡す。

## 作業終了時の報告

- 変更したファイル
- 機能の概要
- テスト結果と未実施項目
- 実機検証の要否
- 仕様差分・リスク・未解決事項
- PRのURL

PRがReady for reviewになりCI成功後、Issueを `status:review` にする。修正依頼時は `status:in-progress` へ戻す。

---

※ 他メンバーへのレビュー依頼・Approve取得は必須ではない。ChatGPTは技術レビューを支援し、プロジェクト管理者が最終判断する。
