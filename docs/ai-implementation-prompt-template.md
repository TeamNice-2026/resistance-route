## 実装手順

1. 関連コードを読み、短い実装方針と影響範囲を説明する。
2. Issueと既存設計が矛盾する場合、独断で変更せず確認する。
3. 必要な実装とテストを行う。
4. 関連するテスト、型チェック、ビルドを実行し結果を報告する。
5. 変更差分を確認し、不要な差分や秘密情報を除く。
6. 作業ブランチにコミットしてPushし、PRを作成する。
7. PRにIssue番号・概要・テスト結果・未解決事項を書く。一次レビュアーを依頼する。
8. **マージせずに作業を終了**する。

## 必須の報告形式

- 変更したファイル一覧
- 追加・変更した処理
- テストコマンドと結果（未実施は理由）
- スマホ実機確認の要否
- 設計からの差分・リスク・未解決事項
- PRのURL

Issueステータスの `status:review` は、Ready for reviewのPRが存在し、CI成功を確認してから変更する。修正を求められた場合は `status:in-progress` へ戻す。
