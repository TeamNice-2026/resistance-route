# プロジェクト要件定義 — Resistance Route

**対象:** 東京電子専門学校周辺の学生向けGPS徒歩ナビWebアプリ  
**チーム:** TeamNice-2026（4人）  
**完成目標:** 2027年2月ごろ  
**文書状態:** 合意済み要件を整理した基礎資料。技術的な細部は未確定のものを含む。

## 1. 背景・目的

池袋周辺では、最短距離であることと、学生が毎日通いやすい道であることが一致しない場合がある。大通り、信号、混雑、路地などの違いを、学生の実体験によって発見・共有できるようにする。

**目的:** 学生が実際に歩いたおすすめ道をコミュニティで共有し、普通の徒歩ルートと比較しながら、通学しやすいルートを選べるようにする。

一般的な地図・ルート探索は既存サービスを利用し、卒業制作の独自性を「GPS実走記録」「実走区間の投稿」「別ユーザーによる通行確認」「コミュニティ情報を加味したルート選定」に置く。

## 2. 対象と制約【確定】

| 区分 | 要件 |
| --- | --- |
| 対象利用者 | 東京電子専門学校の学生を中心とする |
| 対象地域 | 東京電子専門学校を中心とした半径2 km以内 |
| 対象移動 | 徒歩のみ |
| 端末 | GPS機能を備えたスマートフォンを優先 |
| アプリ形態 | Webアプリ、モバイルファースト |
| メイン操作 | 「学校へ行く」で現在地から学校への経路を検索 |
| その他の目的地 | 対象エリア内で任意の目的地検索が可能 |
| GPS利用 | 現在地表示、実走軌跡記録、おすすめ道共有、徒歩ナビ表示 |
| ナビ表現 | 地図上にルート線と現在地を表示・追従。音声による交差点ごとの道案内は不要 |
| GPS記録 | **画面が表示されている間のみ**。バックグラウンド記録は保証しない |
| おすすめ道投稿 | **本人の実走GPS履歴から区間選択して投稿**。自由な手描き投稿は不可 |
| 投稿の公開 | 投稿後すぐ公開し、最初は「新規ルート／未確認」表示 |
| 通行確認 | 別ユーザーの有効な実走履歴が蓄積した場合に「コミュニティ確認済み」へ昇格 |
| 認証 | 登録・ログインあり。閲覧機能は原則ゲスト利用可 |
| 公開目標 | インターネット上からHTTPSで利用できるようにする |
| 開発環境 | 4人ともWindows。VS CodeとCodex / Claude Codeを利用 |
| 開発費 | 必要なら小額の費用を許容。サービス・予算は未選定 |

「コミュニティ確認済み」は、**安全、夜間の安全、私有地でないこと、立入可否を証明するものではない**。

## 3. 想定ユースケース【確定】

### A. 学校への通学
ホームの「学校へ行く」→現在地を確認→最短とおすすめ候補を比較→選んだ経路線を地図表示→徒歩移動中に現在地を確認。

### B. 任意目的地への徒歩移動
対象エリア内の目的地を検索→経路を選ぶ→現在地と経路線を地図表示。

### C. おすすめ道を共有
ログイン→記録開始→画面表示中に実際に徒歩移動→記録終了→自分の履歴の一部区間を選択→タグと説明を追加→公開。

### D. コミュニティの情報を確認
他人の公開おすすめ道を地図で閲覧→参考になった場合は評価→別アカウントの実走記録との重なりで通行確認を蓄積。

## 4. 必須機能（MVP）【確定した機能範囲】

1. 地図表示、対象エリア表示、現在地取得
2. 「学校へ行く」と任意目的地の徒歩ルート検索
3. 最短ルートとコミュニティを考慮したおすすめルートの比較
4. ルート線と現在地の地図表示（追従）
5. ユーザー登録・ログイン・ログアウト
6. GPS実走記録の開始・終了、簡易ノイズ対処、本人限定の履歴
7. 自分の実走履歴の一部区間を選ぶおすすめ道投稿
8. 投稿の地図公開、タグ・説明、「参考になった」
9. 別ユーザーのGPS記録に基づく通行確認と表示ステータス
10. 基本的な削除、権限管理、エラー処理、モバイル操作

**実装上の注意:** ルート探索APIが生成できない別ルートを、スコア計算のみで自動生成できるわけではない。候補が1本ならその制約を画面に明示し、架空の経路を表示しない。

## 5. 発展機能【必須ではない】

貢献ポイント・称号、天候API連携、複雑な投稿管理、広域展開、時刻別の客観的混雑分析、全国規模の自動裏道発見。期限に影響する場合は実装しない。

## 6. 明確な非対象【確定】

自動車・自転車の経路案内、全国版、バックグラウンドGPS保証、音声ターンバイターン案内、独自の道路ネットワークをゼロから構築すること、GPSだけで未登録の道路を自動生成すること、客観的な治安・混雑のリアルタイム保証。

## 7. 検証と完成目標

実機で、地図表示→通学ルート検索→ルート比較→記録開始/終了→履歴→おすすめ区間投稿→別アカウントで閲覧・参考評価→別ユーザー記録による通行確認、を説明できること。

測定する候補：距離・推定所要時間・おすすめ道重複率・GPS補正前後のずれ・学生の主観的な歩きやすさ。**実測していない混雑や安全性は数値で断定しない。**

初期データはチームの実走によって蓄積し、発表当日の電波やGPS不調に備えて**事前収集した許可済みデモデータ**を利用する案を検討する。

## 8. 現時点の開発状況

GitHub上にReact、FastAPI、PostgreSQL/PostGIS、Docker ComposeとCIの最小土台がある。**4人のWindows PCへのクローン・Docker起動確認はまだ行っていない。** 地図・GPS・ナビ本体は未実装。
